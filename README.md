# Enterprise RAG

A multi-tenant document question-answering system built from scratch in Python. Users upload PDFs and ask questions; answers are generated by an LLM using only the retrieved document passages.

## Features

- **Hybrid retrieval**: PostgreSQL full-text search + Qdrant vector search, merged with Reciprocal Rank Fusion (RRF)
- **Multi-tenant isolation**: JWT authentication; every query and document is scoped to the tenant in the token
- **PDF ingestion pipeline**: text extraction (PyMuPDF), chunking, multilingual embeddings (Sentence Transformers)
- **Grounded answers**: Claude answers using only the retrieved context
- **Measured quality**: built-in evaluation script (hit rate and MRR)
## Retrieval quality

Evaluated on 20 questions over two Wikipedia articles (Armenia, Photosynthesis). A question counts as a hit if the top-5 results contain the passage with the answer.

| Method | Hit rate@5 | MRR |
|--|—|--|
| Keyword only | 90% (18/20) | 0.875 |
| Vector only | 90% (18/20) | 0.654 |
| **Hybrid (RRF)** | **100% (20/20)** | **0.975** |

Keyword and vector search miss different questions (keyword misses numbers and word variations, vector misses rare names), so fusing them gives better results than either alone.

This is a small evaluation set, so it shows the trend rather than a final benchmark.
## Tech stack

FastAPI, PostgreSQL, Qdrant, SQLAlchemy, Sentence Transformers (`paraphrase-multilingual-MiniLM-L12-v2`), PyMuPDF, PyJWT, bcrypt, Anthropic Claude, Docker Compose.

## API

| Endpoint | Description |
|--|—|
| `POST /auth/register` | Create a tenant and its first user |
| `POST /auth/login` | Get a JWT access token |

| `POST /ask` | Ask a question about the tenant’s documents (auth required) |

## Getting started
1. Clone the repository and create a virtual environment, then install dependencies:

```
pip install -r requirements.txt
```

2. Create a `.env` file in the project root:

```
ANTHROPIC_API_KEY=your_key
DATABASE_URL=your_postgres_url
QDRANT_URL=http://localhost:6333
JWT_SECRET_KEY=a_long_random_secret
```
3. Start PostgreSQL and Qdrant:

```
docker compose up -d
```

4. Create the database tables:

```
python -c “from app.database import Base, engine; import app.models; Base.metadata.create_all(engine)”
```

5. Run the server:

```
uvicorn app.main:app --reload
```

## Web UI

A simple Streamlit interface lets a user log in, upload a PDF and ask questions without using Swagger.

```bash
streamlit run ui/app.py
```
Open http://localhost:8501. The API must be running on http://127.0.0.1:8000.


## Running the evaluation

Upload your test PDFs through `/documents/upload`, put your questions in `eval/questions.json`, then run:

```
python -m eval.evaluate
```

It prints hit rate and MRR for keyword-only, vector-only and hybrid retrieval, plus the questions each method missed.

## Evaluation

Retrieval quality is measured on a hand-written golden set of 25 questions over 2 documents (~83 chunks, single tenant). A chunk counts as relevant if it belongs to the gold document and contains the gold answer string. K = 1 / 3 / 5.

| Method | Precision@1 | Hit@5 | Recall@5 | MRR |
|--|—|--|--|—|
| Keyword (Postgres full-text) | 0.68 | 0.72 | 0.29 | 0.700 |
| Vector (Qdrant) | 0.52 | 0.92 | 0.28 | 0.691 |
| **Hybrid (RRF)** | **0.92** | **1.00** | 0.38 | 0.948 |
| Hybrid + cross-encoder rerank | 0.92 | 1.00 | 0.38 | 0.953 |

Notes:
- Recall@5 is low by design: some answer strings appear in many chunks (up to 30), so 5 results can never cover them all. Hit rate and Precision are the more meaningful numbers here.
- Reranking looked like noise on the gold metrics, but end-to-end it fixed a real miss: for one question the answer chunk was at rank 9 of the hybrid results, and the reranker moved it to rank 2. A substring false positive (a bibliography chunk containing the same name) had hidden this miss in the hybrid Hit@5, so the true hybrid Hit@5 is about 0.96 (24/25), not 1.00. Reranking over the top-10 hybrid candidates is therefore enabled in the main pipeline.

### Answer and citation accuracy

End-to-end test on the same 25 questions (hybrid retrieval, reranking over the top-10 candidates, Claude answer with cited sources):

- Answered: 25/25
- Answer contains the gold value: 25/25
- Cited source contains the gold value: 25/25
- Out-of-scope questions still rejected: 15/15 (10 off-topic plus 5 trap questions)
Before reranking the result was 24/25. For one paraphrased question the answer chunk ranked 9th, so the system refused instead of guessing. That is the safe failure mode, and it is what led to enabling reranking.


### Guardrails
- Out-of-scope questions: 15 questions whose answers are not in the documents (10 off-topic, 5 trap questions on the same topics as the documents but asking for details that are missing) were all rejected with the no-information reply (15/15). Only 8 of 15 were stopped at retrieval (relevance threshold); the other 7, including all 5 trap questions, reached the model and were rejected by the generation and citation checks.- Out-of-scope questions: 10 questions whose answers are not in the documents were all rejected with “No relevant information found” (10/10). 8 of 10 were stopped at retrieval (relevance threshold), the other 2 by the generation/citation checks.
- Prompt injection: a document containing “ignore all previous instructions” did not change the model’s behavior.
- Every answer returns the source chunks it was based on; answers without a valid cited source are replaced by the “no information” reply.

### Limitations
- Small corpus (2 documents) and small question sets (25 positive, 15 negative): results are encouraging, not a final proof. Planned: a larger corpus and more varied questions.
- Gold labels are based on string matching, not human-annotated chunks. This already produced one false positive (a bibliography chunk matching a name), which is documented above.


### Security & tenant isolation

- Every query is filtered by `tenant_id` taken from the signed access token, never from user input.
- Isolation is tested at two levels:
  - retrieval layer: 3 tenants x 5 queries x 3 search methods (keyword, vector, hybrid) = 45 checks, 0 cross-tenant leaks (`python -m eval.test_isolation`);
  - API layer: user A uploads a document with a unique secret, user B (another company) asks about it and does not see it; requests without a token or with an invalid token get 401 (`python -m eval.test_api_isolation`).
- Passwords are hashed; login and register enforce length limits.
